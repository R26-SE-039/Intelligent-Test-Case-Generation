# Page 6 – Code Review

**URL:** `/dashboard/code-review`

## Simple Speech for Viva

> "This is the Code Review page. This is where the user sees the final test automation code generated by the AI.
>
> When the user arrives here, the system takes three inputs:
> 1. The approved Gherkin scenarios from the Gherkin Editor
> 2. The DOM elements collected by the DOM Inspector
> 3. The framework selected in Mode Setup
>
> The AI combines these three and generates ready-to-run test code.
>
> At the top of the page, there are three tabs – one for each framework: **Selenium**, **Playwright**, and **Cypress**. The user can click any tab to view the code in that framework. Each tab has its own filename, for example `test_suite_playwright.py` or `test_suite_cypress.cy.js`.
>
> The code is shown inside the Monaco editor, with full syntax highlighting. The QA engineer can read the code and edit it directly if needed.
>
> The page has these main buttons:
> - **Generate Code** – calls the AI to generate code
> - **Save** – saves the edited code back to the database
> - **Copy** – copies the code to the clipboard
> - **Download** – downloads the code as a file
> - **Run Tests** – navigates to the Execution page
>
> We also show a *Risk Prediction* section. This is a machine learning model that analyses the test code and predicts which test scenarios are most likely to fail or are most fragile. This helps QA engineers focus on the risky tests first.
>
> If the underlying Gherkin or DOM elements change later, the page shows a *Stale* warning, telling the user that the code may need to be regenerated."

---

## Key points to mention
- AI takes Gherkin + DOM + framework, outputs full test code
- Three frameworks shown side-by-side
- Risk Prediction ML model integration
- Stale detection when inputs change
- Save/Copy/Download/Run options
